Handoff comercial → operaciones

El momento más crítico: cuando el cliente dice "sí". Este handoff define la calidad del kick-off.

📋 Sale Package — entrega comercial
  • Propuesta firmada con scope, precio y condiciones
  • Notas del discovery comercial — dolores y motivaciones
  • Stakeholders del cliente: quién decide, usa, paga
  • Compromisos de timeline dados durante la venta
  • Riesgos identificados en el proceso comercial
  • Contexto cultural del cliente (tamaño, industria, sensibilidades)
🚀 Project Package — recibe el Project Lead
  • Briefing de 30 min con CEO o Country Manager USA
  • Acceso al CRM con todas las notas del deal
  • Intro al cliente hecha por el vendedor (email + llamada)
  • Asignación del equipo India con Chief AI & Delivery
  • Fecha de kick-off acordada con el cliente
  • Repo creado, canales Teams configurados, accesos listos
⚠️ Regla del handoff: El Project Lead no contacta al cliente hasta que el briefing con el vendedor esté completo y la intro haya sido hecha. Un Project Lead sin contexto genera una primera impresión débil que el equipo paga durante semanas.

¿Cómo funciona Andino a nivel de proyecto?

Squads pequeños y enfocados. Chile lidera — cliente, scope y decisiones. India ejecuta el delivery técnico. El framework estandariza cómo se conectan ambos lados.

Modelo de colaboración: Chile es el punto de contacto con el cliente — entiende el negocio, prioriza el scope, valida el output. India traduce ese scope en software con autonomía técnica. La coordinación es complementaria, no jerárquica: cada lado tiene un dominio de ownership claro.

Principios del framework

🎯 Claridad ante todo
  • Cada ticket tiene un owner único
  • Intent documentado antes de codificar
  • Sin trabajo sin contexto escrito
  • Decisiones registradas en Jira/Confluence
⚡ Velocidad asimétrica
  • India opera ~10h de adelanto a Chile
  • Rituales anclados en overlap horario
  • Trabajo asíncrono como default
  • Bloqueos escalados en <2h
🤖 AI-native por defecto
  • Nébula + Claude Code en cada proyecto
  • Context Engine actualizado por sprint
  • Prompts y workflows documentados
  • Métricas de adopción de IA por proyecto

Rituales de proyecto

Diseñados para el overlap horario Chile–India: 14:00–17:00 CLT / 10:30–13:30 IST. Haz clic para ver el detalle de cada ritual.

⏰ Ventana de overlap: ~10h de diferencia entre CLT e IST. Todos los rituales síncronos deben caer entre 14:00–17:00 CLT / 10:30–13:30 IST.

Protocolo asíncrono

📝 Antes de tu turno
  • Actualiza el estado de tus tickets en Jira
  • Deja contexto en PRs abiertos
  • Prepara preguntas en el canal de Teams del proyecto
  • Bloqueos con @mention
🌅 Al empezar tu turno
  • Lee el stand-up escrito del otro equipo
  • Revisa Jira: tickets y comentarios nuevos
  • Responde preguntas antes de codificar
  • Urgente → @mention en el canal
🚫 Nunca asíncrono
  • Decisiones de arquitectura
  • Cambios de scope → llamada primero
  • Bloqueos críticos → escalar inmediato
  • Kick-off de Bolt → siempre en vivo

⚠️ Regla de oro: Si estás bloqueado más de 2 horas, escalas. No esperes el stand-up del día siguiente.

Onboarding al proyecto

Cuando llega un nuevo integrante, este proceso asegura que esté operativo en menos de 1 día hábil.

🇨🇱 Chile — Project Lead
1
Briefing con comercial (30 min)
CEO o Country Manager USA hace el traspaso: negocio del cliente, historia del deal, stakeholders y compromisos dados durante la venta.
2
Leer el Project Brief en Confluence
Stack, decisiones de arquitectura, Bolts anteriores, feedback del cliente y métricas actuales.
3
Meet con India Tech Lead (30 min)
Presentación, expectativas de trabajo, timezone, preferencias de comunicación y acuerdos de disponibilidad.
4
Accesos y canales
Jira, Team en Teams, Confluence. Intro al cliente hecha por el vendedor antes del primer contacto directo.
🇮🇳 India — Dev / Tech Lead
1
Setup técnico (2h máx)
Repo clonado, dependencias instaladas, env local funcionando, Nébula + Claude Code configurado. Sin esto, no hay día 1 productivo.
2
Leer el Context Engine del proyecto
Arquitectura, ADRs, convenciones de código y guías de contribución en Confluence.
3
Primer good-first-issue
Chile prepara un ticket etiquetado para el día 1. Objetivo: un PR chico para conocer el proceso completo.
4
Meet con Chile Lead (30 min)
Expectativas, acuerdos de comunicación, repaso del Bolt actual. Preguntas sin filtro bienvenidas.

Métricas del framework

Métricas en dos niveles: empresa (portfolio, revenue) y proyecto (delivery, colaboración, IA). Revisadas en sus respectivas ceremonias.

🏛️ Métricas de empresa — Portfolio Review mensual

💼 Revenue & pipeline
  • Pipeline value — total deals activos LATAM + USA
  • Win rate — % propuestas que cierran (target ≥40%)
  • Sales cycle — días primer contacto → firma (target ≤21d)
  • Revenue por proyecto — vs. costo operacional Chile+India
📊 Portfolio health
  • Proyectos on-track — % sin riesgo de delivery (target ≥85%)
  • NPS del cliente — encuesta post-Bolt, score agregado
  • Utilización India — % capacidad asignada a proyectos activos
  • Churn — contratos no renovados o cancelados

🔧 Métricas de proyecto — Retro quincenal

📊 Delivery
  • Bolt completion rate — % Units entregadas (target ≥85%)
  • Cycle time — ticket creado → Done (target <5 días)
  • PR review time — PR abierto → aprobado (target <4h)
  • Defect escape rate — bugs post-demo (target 0)
🤖 Adopción IA
  • AI usage rate — % tickets con Nébula/Claude Code (target ≥80%)
  • Context Engine freshness — % docs actualizados en el último Bolt
  • Prompt reuse rate — % prompts del canal #ai-prompts reutilizados
